# WinExplorer 1.4.7 更新说明

**发布日期**：2026-11-21
**一句话**：目录列表改到后台读取 —— 进入超大目录、或打开掉线的网络卷时，窗口不再卡死。

---

## 这次改了什么

### 1. 进目录不再冻窗口

以前切进一个目录，读取是在主线程同步做的：几万项的目录、或者已经断开的 SMB 网络卷，
会让整个窗口停住——连"转圈"都画不出来。

现在读取放到后台，界面立刻可以继续操作：

- 点开的瞬间窗口就响应，列表在新内容到达时整体替换；
- 网络卷超时、权限异常都不再阻塞界面；
- 连续快速点几个目录也没问题（见下）。

### 2. 连点目录不会串台

快速连点两个目录时，先发出的读取可能后回来，把新目录的内容覆盖掉。
现在每次读取都带一个序号，回来的结果序号对不上就整包丢弃 —— **以你最后一次点的那次为准**。

### 3. 状态栏的「正在读取…」

异步之后需要一个"确实在干活"的反馈，所以状态栏左侧会出现小转圈 + 「正在读取…」，
读完自动消失。

### 4. 压缩/解压完成后仍然会选中新文件

这条是异步化带出来的隐患：以前读完目录立刻选中产物，现在读完前列表里还没有它。
已改为"先记下要选中的目标，读完再补选中并滚动到它"。

---

## 你可能会注意到的变化

| 场景 | 现在的表现 |
|---|---|
| 切换目录 | 会**先看到上一个目录的列表** + 状态栏「正在读取…」，读完替换。不再出现空白闪一下 |
| 快速连点多个目录 | 只有最后一个的结果会显示（其它的静默丢弃） |
| 网络卷/巨大目录 | 窗口保持可操作，只是列表更新要等一会 |

没有任何数据格式、偏好设置、快捷键的变更；升级后所有设置原样保留。

## 怎么验证

**自动**（开发用，不碰用户数据）：

```bash
WINEXPLORER_SELFTEST=1 WINEXPLORER_LANG=zh build/WinExplorer.app/Contents/MacOS/WinExplorer
```

预期输出 `SELFTEST OK`，共 **340 项**断言（zh / en 各跑一遍）。本次新增 3 条：

- 异步读目录：会走完加载态
- 异步读目录：结果落到列表里
- 异步读目录：连点不同目录时以最后一次为准

**手动**（建议按顺序点一遍）：

1. 打开一个很大的目录（如 `/System/Library`）——窗口应始终可拖动、可滚动，列表稍后填满；
2. 快速连点两个不同的文件夹，最终停在你最后点的那个；
3. 状态栏在切换时应短暂出现「正在读取…」；
4. 选中几个文件压缩成 zip，完成后新 zip 应被选中并滚动到可见位置；
5. 拔掉/断开的网络卷目录 → 不应卡死，出现错误提示或空列表。

## 已知限制

- **目录监听触发的自动刷新仍是同步的**：外部程序改动当前目录（比如编译输出）后，
  0.25s 防抖结束的那次刷新还在主线程。它需要保留选择与焦点、比对目录签名，
  异步化要另做一套合并逻辑，风险更大，留到后续版本。
- 后台读取**不能中途取消**：快速连点时多跑的那几次枚举会浪费一点 IO（无副作用）。
