# ADR 0002 · 权限的展示与授权交互

- 状态：已采纳（2026-11-21）
- 影响范围：`Models/AccessState.swift`、`Services/PermissionService.swift`、`Services/FileSystemService.swift`、`ViewModels/BrowserModel.swift`、`Views/FileItemIcon.swift`、`Views/AccessRequestView.swift`

## 背景

用户在浏览受保护的内容时，最烦的是"一进目录就被弹一堆框"。macOS 上真正会发生弹窗的只有两类：

1. **TCC**（隐私保护）：首次读桌面 / 文稿 / 下载 / 外置卷时，系统弹一次「"WinExplorer"想访问…」。粒度是**目录**，不是文件，且由系统控制，App 无法用代码绕开。
2. **POSIX / ACL**：`EACCES`。这类完全不会弹窗，只是读失败。

也就是说：**列一个目录本身不可能为每个子项弹窗**——除非 App 自己对每个子项做"会触发访问的动作"（取图标、读大小、递归统计、打开文件）。旧代码里有三处这样的动作没有区分对象：

- `IconProvider.icon(for:)` → `NSWorkspace.icon(forFile:)`，对每个可见行都调；
- `FolderSizeService.measure` → 对整个子目录递归枚举；
- `QuickLookController` / `NSWorkspace.open` → 直接对目标动手。

## 决定

### 1. 一切探测都必须只读

- `FileSystemService` 的 `resourceKeys` 增加 `.isReadableKey`：和原有的 `isDirectory` / `fileSize` 等**同一次 stat** 拿到，不额外付系统调用，也不触发任何访问。
- `FileItem.access`（`.granted` / `.denied`）就是这一项的结论；`nil`（系统没给结论）按 `.granted` 处理，宁可不加锁也不误伤正常文件。
- 列目录、画行、算大小、搜索，全部**不打开文件、不取未授权项的图标、不递归未授权目录**。

### 2. 未授权项：变淡 + 锁，但不消失

- 行整体 `opacity 0.42`（剪切态 0.5，取更淡者）；图标换成同色系的淡 `<doc|folder>.fill` + 右下角橙色锁徽标（16pt 行里 8pt 的锁才认得出）。
- 列表里**照常列出**名字、类型、修改时间，只是不显示大小（`—`），因为读不到就是读不到，不能把统计出来的 0 当成"空文件夹"。
- `FolderSizeService` 与状态栏的统计进度都跳过 `denied` 目录，否则进度永远差几个、百分比永远到不了 100%。
- 悬停提示写明「未授权：需要授权后才能打开」，避免用户以为文件坏了。
- 状态栏显示「N 项未授权」（橙色），不打断任何操作。

### 3. 只有主动操作才提示，且只针对那一项

统一在 `BrowserModel.blockedByUnauthorized(_:)` 一个拦截点：

| 入口 | 行为 |
|---|---|
| 打开（双击 / Enter / 右键打开） | 弹授权浮层，不打开 |
| 空格 Quick Look | 弹授权浮层（否则预览面板会是一片空白） |
| 复制 / 剪切 / 移到废纸篓 / 彻底删除 | 弹授权浮层，不做半截操作 |
| 压缩 / 解压 | 弹授权浮层 |
| 进入目录（地址栏 / 导航）被 `EACCES` 拒绝 | 弹授权浮层，而不是一行技术性错误条 |
| 改属性（⌘I）、重命名 | **不拦**：⌘I 只是读元数据，重命名只需要父目录写权限 |

浮层里就三件事：说清是哪一项、为什么、以及两个入口——「在 Finder 中显示」和「选择此项目以授权…」。

### 4. 授权入口 = 一次显式选择 + 重新探测

- 「选择此项目以授权…」拉起 `NSOpenPanel`，预置到该项所在目录并预填文件名，让用户**明确指向**这一项。
- 回来只做一件事：`isReadable` 重新探测。
  - 通过 → 刷新列表让锁和淡化消失（若是"进不去目录"则直接进去）；不替用户执行原本的操作，避免"授权即执行"的惊吓。
  - 不通过 → 再弹一次，并说清原因（文件自身权限位 / 只读卷），引导去 Finder 的「显示简介 → 共享与权限」。
- TCC 保护的位置（桌面 / 文稿 / 下载 / 外置卷）额外给「打开系统设置」，直达「隐私与安全性 → 文件与文件夹」。

### 5. 嵌套目录：逐项判定，父级不连带

- 每次 `load` 都对每个子项独立算 `access`，因此"父目录放开、子目录仍被锁"完全能表达。
- 授权某个文件后 `refreshFromDisk()` 会重算所有行；权限被**收回**时（`contentsOfDirectory` 抛 `EACCES`），已加载的行统一降级为 `denied` 并给出授权入口，不会继续显示过期内容。
- `directorySignature` 带上 `access.rawValue`，权限变化本身就能触发列表刷新。

## 取舍

- **不引入沙盒 / 安全作用域书签**：本 App 是非沙盒的通用文件浏览器（沙盒下无法浏览任意路径）。所以「授权」在这里的语义是「用户显式确认 + 重新探测」，它**不能**改变 POSIX 权限位，也不能替代 TCC 授权。这一点在浮层文案和 README 里都写明了，不做虚假承诺。
- **不做"全部授权"批量按钮**：与"不要逐个弹窗"的初衷相悖，且批量面板在非沙盒下拿不到额外权限。
- **不给未授权项取系统图标**：既省 IO，也避免为了画一个图标去碰受保护的文件。

## 后果

- 进入一个满是受保护子项的目录：**零弹窗**，全部淡显 + 锁；只有点开某一项才出现一次提示。
- 自检新增 22 项：`chmod 000` 的文件/目录被标记为 `denied`、列目录不产生请求、主动打开只提示该项、进入未授权目录给浮层而非错误条、授权父目录后子项仍各自判定、授权后状态回到 `granted`、权限错误识别不误伤"文件不存在"。
