# ADR 0009 · 标签视觉改为 Windows 11 标签卡

- 状态：已实施（v1.4.3）
- 修订：[ADR 0006](0006-tab-bar-in-toolbar-and-file-transfer.md) 的 chip 视觉部分、
  [ADR 0008](0008-toolbar-tabs-left-aligned-no-title.md) 的 chip 视觉细节
- 起因：用户贴出 Windows 11 资源管理器的实机截图，要求「搞这种 tab 样式」——
  白色圆角标签卡浮在灰色标签带上，而不是此前的 accent 淡蓝药丸。

## 决定

标签 chip 的视觉全部按 Win11 资源管理器的标签卡重做：

| 状态 | 视觉 |
|---|---|
| 激活 | 白色圆角卡片（`textBackgroundColor`，深色模式自适应成深卡片）+ `primary 10%` 细边框 + 轻投影（`black 16%`，radius 2，y 1），**不用任何 accent 色** |
| 未激活 | 完全透明（只剩图标 0.75 透明度 + 次级文字色），与工具栏底色融为一体 |
| 悬停 | 浮出 `primary 6%` 浅色卡（Win11 同样行为） |
| 关闭按钮 `×` | 激活标签常显；未激活标签悬停才显示。槽位恒定保留（用透明度控制显隐），避免悬停时整卡宽度跳动 |
| 拖文件悬停 | accent 描边高亮 —— 这是功能反馈而非装饰，Win11 拖放时同样高亮目标标签，保留 |

## 为什么换掉 accent 药丸

之前的「accent 16% 底 + accent 35% 描边」是 macOS 通用的选中语义，但它有两个问题：

1. **语义冲突**：accent 高亮在这套 UI 里已经同时承担「选中」「拖放目标」「焦点」
   三种含义，激活标签再用 accent 就分不清状态；Win11 用「白卡片 vs 透明」的
   材质对比表达激活，accent 留给真正的交互反馈。
2. **视觉重量**：淡蓝药丸在浅灰工具栏上是一块彩色斑，Win11 的白卡片靠投影
   浮起，安静得多，和用户截图里的形态一致。

深色模式用 `NSColor.textBackgroundColor`（浅色=纯白，深色=深卡片底）而不是
写死白色，卡片在两种外观下都是「内容表面」这一语义。

## 取舍

- 不做 Win11 标签的梯形切角（左右下角斜切 + 底部小凹槽）：macOS 工具栏里
  画非矩形路径要走 Canvas/自绘，收益小；圆角 6 的白卡片已能表达同一种语言
- 激活卡片投影用 `compositingGroup` + `shadow`，阴影极轻（16% 黑）——
  投影太重会在深色模式下发灰
- 未激活标签的 `×` 用透明度隐藏而非条件移除：保留槽位 = 悬停不跳宽

## 验证

- SelfTest 全量 zh / en PASS（视觉改动不影响模型层）
- 像素测量（`WINEXPLORER_SNAPSHOT_FULL=1`，浅色 / 深色各一张）：
  - 浅色：卡片内 `255,255,255`，边框 `210` 细线，卡外工具栏 `249`，投影渐变可见
  - 深色：卡片内 `30,30,30`，边框 `57` 亮细线，卡外工具栏 `40`
  - 三标签：激活卡白底（x 363-455），未激活两卡全透明；
    `×` 槽位深色像素计数 激活=75 / 未激活=0,0

## 修订：标签卡尺寸契约（高度驱动）

用户要求「高度占满可用区域（特别是下方），只需设置高度即可生效，不需要额外
固定宽度或其他尺寸参数；宽度、斜边和顶部/底部对齐随容器自适应，形状在不同
尺寸下不变、高度不被压缩」。实测 Win11 参考图得到比例：顶圆角 ≈ 0.19×卡高、
底边贴齐标签带下沿。

据此定下尺寸契约（`TabCardShape` + `TabBarView`）：

| 项 | 来源 |
|---|---|
| 顶圆角 / 底部凹圆角 / 外撇 | `rect.height` × 固定比例（0.18 / 0.20 / 0.18）—— 形状在任何高度下比例不变 |
| 竖边位置 | `rect.width` 减去外撇量，窄容器自动收窄 —— 宽度随容器 |
| 卡片高度 | 填满容器（`maxHeight: .infinity`），底边落在容器底 = 底部贴齐 |
| 标签条总高 | 唯一需要显式设的尺寸：`TabBarView.trapezoidBarHeight = 52`（= 工具栏 item 高），顶部呼吸按 10% 派生 |

踩到的坑（重要）：SwiftUI 工具栏 item **连高度也只按理想值提案** —— 只写
`maxHeight: .infinity` 时 chip 会塌回内容高（实测只剩 18pt、上下悬空）。
所以必须自己把标签条总高定下来（一个常量），chip 内部的 `maxHeight` 才吃得满。
已知局限：52 是对当前 `.unified(showsTitle: false)` 工具栏的实测值，若工具栏
样式变化需要同步这个常量。

验证：对比视图（只设条带高 52）里白卡纵向 52pt 全高、梯形底脚比竖边外扩；
自检 zh / en 全 PASS。
