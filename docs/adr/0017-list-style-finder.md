# ADR 0017 · 列表视图样式对齐访达

- 状态：已实施（v1.4.10）
- 起因：用户对照访达列表视图，要求三件事：列之间要有清晰的分隔符（方便拖动列宽）、
  相邻行交替条纹、选中高亮的高亮区域宽度/左右留白/圆角要匹配访达比例。
  约束：只改样式，布局与内容不变。

## 决定

### 1. 列分隔线

- 位置统一由 `FileListLayout.dividerX(...)` 推算 —— 表头与行用的是**同一个函数**，
  所以线天然对齐（实测三条线都落在 538 / 644 / 881pt）。
- 表头：原本就有 7pt 宽的透明拖拽热区（`dividerHandle`），现在在热区里叠一根可见线；
  悬停时线从 1pt 变 2pt 并转强调色，明确提示「这里可以拖」。
- ~~行内：同样位置画一根线，被选中高亮盖住~~ → **修订（v1.4.11）：行里不画线**。
  列边界只属于表头（那是拖拽列宽的手柄），行内画线会把列表切成格子，既不符合访达
  的观感，也干扰读内容。用户也明确要求「其他行、单元格或内容区域不要显示任何列分隔线」。
- 颜色用 `Color.primary.opacity(0.26)` 而不是 `separatorColor`：后者叠在表头底色上
  实测只差 5 级灰，等于看不见。26% 实测浅色 199（与白底差 56）、深色 79（与底差 49），
  一眼能看出列边界。

### 2. 交替条纹

用 `NSColor.alternatingContentBackgroundColors[1]`，与行底色（`textBackgroundColor`）
交替。选它而不是手写灰色，是因为系统已经调好两个模式下的对比度：
浅色 255 / 244，深色 30 / 41，都是「看得出但不抢内容」的幅度。

`detailsContent` 的 `ForEach` 改为带索引的 `Array(items.enumerated())`，用奇偶决定
是否铺条纹。

### 3. 选中高亮

改成访达的比例，抽成常量：

| 项 | 值 | 说明 |
|---|---|---|
| 圆角 | 5pt | 比 Windows 直角柔和，和访达一致 |
| 左右留白 | 5pt | 不贴窗口边缘 |
| 上下留白 | 1pt | 几乎贴满行高 |

## 踩到的两个坑（都留了注释）

1. **`background` 的层叠顺序是「先写的在上层」**。把条纹写在前面会把选中色盖掉，
   表现为「选中行只有下半截是蓝的」。高亮必须写在第一个 `background`。
2. **`background` 只覆盖内容尺寸**。`FileRow` 的内容高约 16pt，而外层 `.frame(height: 26)`
   是 26pt；不先 `.frame(height: rowHeight)` 再挂 `background`，条纹只会画成一条细带，
   上下各露出约 5pt 父视图底色（表现为「白 36pt + 灰 16pt」的怪周期）。

## 取舍

- **只在「详细信息」视图做条纹**：「列表」和「图标」视图没有列概念，加条纹收益不明显，
  且用户的要求明确指向带「大小 / 种类」列的视图。
- **行内线不随选中变白**：直接让高亮盖住线，比在上层重画一根白线简单且不会有
  1px 错位。
- **列宽拖拽的交互没改**：只是让原本存在的 7pt 热区变得可见。

## 验证

- 像素实测（2x 截图，逻辑坐标换算后）：
  - 条纹严格 26pt 交替，浅色 `255/244`、深色 `30/41`；
  - 表头与行内竖线在 538 / 644 / 881pt 三处完全重合；
  - 选中行高亮 24pt 高（26 − 上下各 1）、左右各内缩 5pt、圆角 5；
  - **v1.4.11 复测**：三条竖线在 569 / 675 / 881pt，浅色 rgb 199、深色 rgb 79；
    行区域（120–400pt）同列取样只有条纹色与选中色，没有任何线残留。
- 自检 zh / en 全 `SELFTEST OK`（样式改动不涉及模型，无断言变化）。
- 验收图：`docs/screenshot-1.4.10-list-light.png`、
  `docs/screenshot-1.4.10-list-dark.png`、`docs/comparison-1.4.10-list-style.png`。
- 新增截图钩子 `WINEXPLORER_KEYS=select:<index>`，用于选中第 N 行做视觉验收。

## 修订：列宽拖拽光标（v1.4.12）

用户要求「鼠标在分隔线上时要变成竖线两边有箭头的样式」。原来用的是
`NSCursor.resizeLeftRight`（只有左右箭头，没有中间竖线）。

先试了系统的 `NSCursor.columnResize`：Swift 侧要求 macOS 15+，而且实测它的
`.image` 与 `resizeLeftRight` **返回同一张位图**（像素数、包围盒完全一致），
拿不到真实外观，没法确认最终效果。

于是改为自绘（`FileListView.DividerCursor`）：

- 形状：1.5pt 竖线（高 16）+ 左右各一个实心三角箭头，整体约 19×16pt；
- 2x / 1x 两份表示，Retina 下清晰；
- 先描 3pt 白边再填黑，深色背景（暗色模式、深灰行）上也有轮廓；
- 热点放在正中心，拖动时竖线正好压在列边界上。

另外在拖动的 `onChanged` 里每帧重新 `set()`：热区只有 7pt 宽，拖动时鼠标容易
移出去，`onHover` 会把光标换回箭头，钉一次可以保证整个过程都是列宽光标。

验收图：`docs/comparison-1.4.12-column-cursor.png`（左：旧光标，右：新光标）。
