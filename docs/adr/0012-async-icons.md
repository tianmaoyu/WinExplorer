# ADR 0012 · 列表图标异步化

- 状态：已实施（v1.4.6）
- 起因：性能排查的 P0 之一 —— 行视图在 `body` 里同步调 `NSWorkspace.icon(forFile:)`，
  首次渲染一个有几百项的目录就是几百次同步 LaunchServices + 文件读取，全压在主线程。

## 决定

`IconProvider` 拆成三个入口，按「一次画几个」来选：

| 入口 | 谁用 | 行为 |
|---|---|---|
| `cached(for:)` | 行视图首帧 | 只查缓存，**绝不触发系统调用** |
| `iconAsync(for:)` | 列表行（详情 / 列表 / 图标视图） | 命中缓存直接返回；否则串行后台队列生成，回主线程 |
| `icon(for:)` | 标签 chip、路径栏、侧边栏、属性面板 | 同步，保持原样（这些地方一次只画一两个） |

行视图（`FileItemIcon`）改成：

1. `.task(id: loadKey)` 驱动加载，`loadKey = 路径 + 是否用通用图标` —— 改名或权限变化都会重新取；
2. 缓存命中时**同步赋值**，首帧就是真图标（不闪占位）；
3. 未命中时先画**同尺寸 SF Symbol 占位**（`folder.fill` / `doc.fill`，30% 灰），
   取到后替换 —— 图标尺寸一致，不会引起行布局跳动；
4. `Task.isCancelled` 检查：行被回收后丢掉结果。

配套：缓存上限 600 → **2000**（大目录滚动时 600 会被反复淘汰，淘汰后又要重新问系统）。

## 取舍

- **串行队列而不是并发**：一次只生成一个图标，避免几百个请求同时打 LaunchServices；
  图标生成是毫秒级，可见行（几十个）串行跟进完全够用。
- **占位会出现一瞬间**：慢盘 / 网络卷上能看出「先灰后彩」。这是异步的必然代价，
  换来的是滚动和进目录不再卡顿。
- **没有做请求中断**：行滚出视口后后台任务仍会跑完并写缓存（结果无害，下次命中反而更快）；
  只丢掉界面回填。
- 图标仍按 16pt 缓存：图标视图放大到 64pt 会略微发软，这是既有行为，本次不改
  （要改得按尺寸分缓存，属于另一件事）。

## 验证

- 自检 **337 项**断言 zh / en 全 PASS，新增 2 条：取过之后能命中缓存、重复取返回同一实例。
- 既有用例「媒体资料库子目录避开系统图标」「照片图库包避开系统图标」「桌面仍用系统图标」
  等 5 条图标策略断言仍全通过 —— 通用图标分支没被异步改造破坏。
- 实机冒烟：打开 `Sources/WinExplorer`（几十个 .swift），截图后按行统计图标列彩度，
  **79 个采样行含彩色像素** —— 说明回填的是系统真图标（占位是纯灰符号，不会产生彩度）。
