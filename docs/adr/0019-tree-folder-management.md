# ADR 0019 · 参考访达的树形文件夹管理

- 状态：已实施（v1.5.0）
- 起因：用户要求「以树形结构展示文件夹及其中的项目，节点支持展开/折叠，选中后显示
  从根目录到当前层级的路径」，并支持创建 / 重命名 / 删除文件夹、向指定文件夹添加、
  把项目移动到其他文件夹、删除文件夹时明确级联规则。
- 关联：[ADR 0013](0013-async-directory-load.md)（目录异步读取）、
  [ADR 0016](0016-context-menu-hang-and-runlog.md)（列表重建成本）

## 关键决定：不建「树对象」

磁盘本身就是树。再造一棵内存树会带来两个问题：内容会与磁盘不同步，
而且每次刷新都要整棵重建。

所以只保存两样东西：

| 状态 | 类型 | 作用 |
|---|---|---|
| `expandedPaths` | `Set<String>` | 哪些文件夹是展开的 |
| `treeChildren` | `[String: [FileItem]]` | 展开过的文件夹里有什么（懒加载，读过就缓存） |

渲染时把两者「扁平化」成 `[TreeRow]`（`item` + `depth` + `isExpanded`），
交给现有的 `LazyVStack`。这样**列表的行视图、选择、拖拽、右键菜单全部不用改**，
只是名称列多了一个缩进和一个展开三角。

### 唯一标识

用 **URL**（`TreeRow.id`）。文件系统里路径天然唯一，不需要额外造 ID，
也不怕重名——重名只可能出现在不同目录。

但**集合键必须用标准化后的路径字符串**（`Self.treeKey`），不能用 `URL` 本身：
`/tmp` 与 `/private/tmp`、末尾斜杠这些差异会让 `Set<URL>.contains` 判不相等。
这是实现时踩到的第一个坑——`cached=1` 但展开后一行都没多出来，就是因为它。

### 父子关系

不维护 parent 指针，靠**路径前缀**判断：
`child.path.hasPrefix(parent.path + "/")`。

折叠父级时把满足前缀的所有后代一起移出 `expandedPaths`，
否则重新展开父级时，里面的子节点会「记着」自己上次是展开的。

## 懒加载

点三角才读子目录（`FileSystemService.contents`，后台队列），读完回主线程写缓存并重建。
读失败（权限 / 已删除）也写一个空数组占位，避免每次重建都重发一次必然失败的请求。

行上的展开三角在读取期间显示小转圈（`loadingTreePaths`）。

## 搜索时退化为扁平

搜索本来就只针对当前层（不递归子目录）。树形展开会让「搜索到底搜不搜子层」变得含糊，
所以 `usesTreeLayout` 在 `searchQuery` 非空时返回 false，直接显示扁平列表。
清空搜索后恢复原来的展开状态。

## 增删改移

| 操作 | 落点 / 行为 |
|---|---|
| 新建文件夹、新建文件 | 快捷键与工具栏**始终建在当前目录**；右键某个文件夹 → 「在此文件夹中新建」才建在它里面 |
| 重命名 | 行内编辑，改完 `reload()` |
| 移到废纸篓 | **先确认**，确认框列出级联数量 |
| 彻底删除 | 原有确认框，同样列出级联数量 |
| 移动到其他文件夹 | 右键「移动到…」→ 选目录；或直接拖到目标文件夹行（原有能力） |

新建落点为什么不用「选中项」推断：连按两次 ⇧⌘N 时，第一次新建完会选中新文件夹，
第二次就会建到它里面，一层层嵌套下去。**自检直接抓到了这个回归**，于是改成显式参数。

## 级联删除

访达行为：删除文件夹 = 连同子项一起删（进废纸篓可恢复 / 彻底删除不可恢复）。

确认框进入时**异步数一遍**里面的东西（上限 2000 项，只为给个量级，不值得为几十万文件卡住），
显示「其中包含 3 个子文件夹、12 个文件，会一并删除」。

删除后的状态一致性：
- `reload()` → `invalidateTreeCache(keepingExpansion: true)` 清子项缓存；
- 同时把**已不存在于磁盘的路径**从 `expandedPaths` 里剔掉，不留幽灵展开态；
- 仍然存在的展开目录会重新读一遍（`reloadExpandedSubtrees`）。

## 选中路径

状态栏右侧原来固定显示当前目录，现在改为：**选中单个节点时显示该节点的完整路径**
（从根到当前层级），并带文件夹/文件图标、可选中复制；未选中时仍显示当前目录。

没有改面包屑：面包屑是导航控件（每段可点），让它跟着选中项变化会让人分不清
「我在哪」和「我选中了什么」。

## 取舍

- **只做「详细信息」视图**：列表 / 图标视图没有列概念，层级缩进在里面没有意义。
- **不做键盘左右键展开**：方向键目前用于上下移动焦点，加入左右展开会改变现有手感，
  留作后续。
- **子层排序不缓存**：每层展开时现排一次（`FileSystemService.sort`）。子层项目数
  通常不大，缓存收益低于复杂度。
- **递归深度上限 24**：符号链接指回祖先时不会把栈打爆。

## 验证

- 自检新增 11 条断言：初始只显示当前层、展开后子项进入列表、子项缩进一层、
  父节点标记为已展开、可以展开到第三层、两层各自被记住、折叠父级会连同后代收起、
  折叠后回到单层、新建落在指定文件夹里、搜索时退化为扁平、全部收起后没有残留。
- 截图验收：`docs/screenshot-1.5.0-tree-light.png` / `-dark.png`（两层展开 + 选中子项）。
- 实测缩进：depth 0 内容起点 225pt，depth 1 为 238pt（每层 13pt）；
  展开三角只出现在文件夹上，文件留等宽空白保持图标对齐。
