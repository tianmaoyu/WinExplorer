# ADR 0021 · 拖拽移动后目标文件夹看不到文件

- 状态：已实施（v1.5.2）
- 起因：用户把一个文件拖到另一个文件夹，重新打开目标文件夹看不到它，怀疑缓存没刷新。
- 关联：[ADR 0019](0019-tree-folder-management.md)（树形展开与子项缓存）、
  [ADR 0020](0020-tree-refresh-blanking.md)（刷新时的缓存策略）

## 排查路径

按「移动是否成功 → 路径对不对 → 是否被过滤 → 缓存是否过期」的顺序逐项排除：

| 排查项 | 结论 |
|---|---|
| 移动是否成功 | 同卷移动走 `FileManager.moveItem`，同步执行，失败会进 `errorMessage`。**磁盘层面几乎不会静默失败** |
| 目标路径是否正确 | `drop` 里按 `targetDir.appendingPathComponent(source.lastPathComponent)` 算，重名会整批拒绝。路径本身可靠 |
| 是否被隐藏 / 过滤 | 新移入的文件不会带 `.` 前缀；搜索词非空时列表会退化为扁平（这点要用户确认搜索框是否为空） |
| **缓存是否过期** | **命中**，见下 |

## 根因：展开时用了旧缓存

`toggleExpanded` 展开一个文件夹时调的是：

```swift
ensureChildrenLoaded(url)   // force 默认 false：有缓存就直接用
```

缓存什么时候建立的？**上一次展开它的时候**。

于是这条正常操作序列会丢文件：

1. 展开文件夹 B（缓存 B 的内容，此时是空的 / 没有新文件）
2. 折叠 B（`expandedPaths` 移除，但 **`treeChildren` 里的缓存保留**）
3. 把文件从 A 拖到 B —— `execute` 里只 `reload()` 了**当前目录 A**；
   `reloadExpandedSubtrees()` 也只会重读**当前还展开着**的目录，B 折叠着，不在其中
4. 再展开 B → 用的是第 1 步的旧缓存 → **看不到刚移进去的文件**

第 2 步保留缓存是 ADR 0020 故意做的（避免刷新时行数塌陷），
但「保留」的前提是**重读时机要覆盖到它**，而展开恰好没有覆盖。

## 修法

展开时强制重读：

```swift
expandedPaths.insert(key)
ensureChildrenLoaded(url, force: true)
```

代价是每次展开多一次目录读取（几十毫秒，且读的时候旧内容继续显示，不会闪空白）；
收益是展开后看到的一定是磁盘上的真实内容。用户点展开的频率很低，值得。

同时把移动结果写进运行日志，下次可以直接从日志判断「到底移没移成」：

```
[user] 移动完成 1/1 → ~/code/test1 失败=0
```

## 给用户的排查清单（有序）

1. **看运行日志**（帮助 → 打开运行日志），找 `移动完成` 那行：
   - `1/1 失败=0` → 移动成功，问题在显示
   - `0/1 失败=1` → 移动失败，紧跟的 `errorMessage` 会说明原因（权限 / 重名 / 跨卷）
2. **搜索框是否为空**：有搜索词时列表只显示匹配项（且退化为扁平）
3. **「显示隐藏文件」是否关闭**：目标文件如果原本是隐藏文件，移过去仍然隐藏
4. **目标路径是否看对**：截图里出现 `<user>/Users/<user>/code/...` 这种嵌套，
   磁盘上确实存在多份同名的 `test1` / `Users`，很容易在错的副本里找
5. **重新展开目标文件夹**（别只看折叠状态）—— 这一版之后展开一定会重读

## 验证

- 自检新增 4 条，走的正是这条路径：
  - 移动前：目标目录展开过（缓存已建立）
  - 移动前：目标目录已折叠
  - 拖拽移动：源文件已不在原处 / 文件到了目标目录
  - **拖拽移动：重新展开能看到移入的文件**
- 全部自检 zh / en `SELFTEST OK`。

## 取舍

- **没有在任何文件系统写操作后清空全局树缓存**：那会退回到 ADR 0020 修掉的
  「刷新时整片消失」。正确做法是让**读取时机**（展开）负责新鲜度，
  而不是让**写入时机**去清空别人正在看的缓存。
