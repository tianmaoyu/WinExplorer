# ADR 0001 · 地址栏视觉对齐 Windows 11

- 状态：已采纳（2026-11-21）
- 影响范围：`Views/PathBar.swift`、`Views/PathField.swift`、`Views/SearchField.swift`

## 背景

旧地址栏没有容器，面包屑直接铺在窗口底色上，并且给「当前目录」那一段加了 `accentColor 12%` 圆角底。实际使用中这一条被读成了「输入框 / 标签条」：蓝色胶囊像被选中的 chip，右侧搜索框又是另一个独立的框，整行缺少「这是一个整体控件」的边界。

Windows 11 资源管理器的地址栏是另一种构图：**一整条浅色圆角容器**（约 28pt 高、1px 细描边），左侧一个当前位置图标，中间是路径段，**当前目录只用字重区分、没有任何底色**，段间是很轻的 `›`；路径过长时折叠中段而不是横向滚动；右边是独立的搜索框。

## 决定

| 维度 | 决定 |
|---|---|
| 容器 | 圆角 6、高 28，填充 `controlBackgroundColor @ 55%`（深浅色都由系统色叠出来），描边 `primary @ 9%` |
| 行高 | 38（容器 28 + 上下各 5），地址栏与搜索框同高 |
| 当前目录 | 去掉蓝色胶囊；`primary` + `.medium`，其余段 `secondary` + `.regular`；悬停给 `primary @ 7%` 圆角 4 底 |
| 位置图标 | 容器最左 16pt，取当前目录的系统图标，仅装饰、不响应点击（点击穿透到「进入编辑」） |
| 分隔符 | `chevron.right` 7.5pt semibold，`primary @ 30%` |
| 溢出 | 段数 > 5 时折叠为「首段 › … › 末两段」；`…` 是下拉菜单，列出被折叠的段，点其中一项直接跳转 |
| 编辑态 | 复用同一容器：`textBackgroundColor` 填充 + `accentColor` 1.5pt 焦点环（错误时改红），不再嵌套第二层圆角框 |
| 搜索框 | 与地址栏同高 28，占位文案带当前目录名（`搜索「下载」`），对齐 Win11 |
| 拖放反馈 | 保留蓝色描边 + 18% 底，这是功能反馈，不能省 |

**交互零变更**：点空白进编辑、`⌘L`、Enter 提交、Esc 取消、Tab 补全、把文件拖到某一段、从某一段拖出，全部保持原行为；本次只新增悬停反馈与折叠菜单。

## 取舍

- **折叠阈值按段数而非实测宽度**：Win11 是按像素宽度算的。SwiftUI 里做真实宽度测量需要 `GeometryReader` + 每段字号测量，复杂度高且容易在窗口缩放时抖动。折中为「段数 > 5 就折叠末两段」，覆盖绝大多数深路径；信息不丢，因为 `…` 菜单能列出全部被折叠的段。
- **不用固定 hex 颜色**：深浅色模式共用一套语义色，避免出现「浅色好看、深色刺眼」。
- **位置图标不可点**：Win11 点图标没有行为，这里让它穿透到空白区（进入编辑），避免出现一个点了没反应的死区。

## 后果

- 地址栏从「一堆标签」变成「一条路径控件」，与 Win11 的视觉层级一致。
- 编辑态只有一层边框，焦点环不会和容器描边打架。
- 自检里没有任何断言依赖面包屑的视觉，本次改动不影响 233 项自检的正确性；折叠逻辑属于纯函数，可用快照钩子人工验收。
