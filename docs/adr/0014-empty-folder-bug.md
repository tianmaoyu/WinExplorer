# ADR 0014 · 修复「偶尔打开文件夹后列表为空」

- 状态：已实施（v1.4.8）
- 起因：用户反馈偶尔打开文件夹（截图里是 `~/Downloads` 和 `/Users`）后列表一片空白。

## 根因

两条独立的原因都会造成"看起来是空文件夹"，本次一起堵掉。

### 1. 属性读取失败时把整项丢掉了（主因）

`FileSystemService.contents(of:)` 原来是：

```swift
for url in urls {
    if let item = makeItem(for: url) { result.append(item) }   // makeItem 读属性失败 → nil
}
```

而 `makeItem` 在 `resourceValues(forKeys:)` 抛错时返回 `nil`。只要某一项读不到属性
（TCC 未授权、目录权限不足、网络卷瞬时抽风），**那一项就静默消失**；赶上整层都读不出来，
文件夹就变成空列表——没有错误提示、没有授权入口，用户只能认为"这里真的没东西"。

排查时的决定性证据：给一个**真的空目录**截图，表头（名称/大小/修改日期/种类）照常显示；
而用户截图里连表头都没有 → 说明不是"数据为空"，是列表把每一项都丢了（表头所在的
`LazyVStack` 内容整体高度塌掉）。四个确定性场景（`/Users`、`~/Downloads` × 单标签/新标签）
都没复现，符合"依赖瞬时权限/IO 状态"的特征。

### 2. 读取卡住时没人收尾

`load` 的完成回调带代次校验，代次不符就 `return`（正确）。但如果**最后一次**读取因为
任何原因一直没有回来，`isLoadingDirectory` 就永远为真、列表永远停在旧内容或空 ——
新建标签后模型本来就是空的，于是表现为"空列表"，而且没有任何超时提示。

## 决定

1. **`makeItem` 永不返回 nil**：属性读不出来时降级成占位项 ——
   名称取 `lastPathComponent`，`kind = 「无法读取」`，`access = .denied`；
   是不是目录用一次 `fileExists(isDirectory:)` 兜底，stat 也失败就按文件画。
   这样用户能看到"有这么个东西 + 锁"，点它会走已有的授权流程，而不是面对一个空目录。
2. **读取看门狗**：每次 `load` 起一个 5s 定时器。
   - 超时且仍是当前代次 → 自动重试一次（新代次）；
   - 再超时 → 清掉加载态并给出「读取『X』超时，请重试」，错误条上本来就有「重试」按钮。
   成功应用结果时取消看门狗、清零重试计数。
3. **诊断开关**：`WINEXPLORER_LOAD_DEBUG=1` 时打印每次读取代次、目录、项数、以及是否被丢弃
   （`[Load] gen=3/3 应用结果 /Users items=2`）。这个 bug 是偶发的，下次复现可以直接看日志。

## 取舍

- 降级项会把"读不到属性的目录"画成文件图标（stat 也失败时无法判断类型）。宁可图标不准，
  也不要让一行凭空消失——后者会被误读成"文件夹是空的"。
- 看门狗只重试一次：自动重试太多次会在真正的权限/网络问题上刷屏。
- 没有改动排序/过滤逻辑，也没有给空目录加特殊 UI：真空白目录本来就该显示表头 + 空列表。

## 验证

- 自检新增 3 条（chmod 000 的目录里取子项属性必然失败，用它造降级路径）：
  - 属性读不出来时降级成占位项
  - 降级项标记为未授权
  - 降级项仍保留文件名
- 全量自检 **343 项** zh / en 双语 PASS。
- 实验对照：空目录截图里表头仍在（证明"空文件夹"与"列表丢失"是两种不同表现），
  本次修复针对后者。
- 复现/验证方法（手动）：
  1. 造一个 `chmod 000` 的子目录放进某文件夹 → 该文件夹应照常列出其它项，
     不因为一项读不到就整体变空；
  2. 若整层都读不到 → 行仍在（带锁），不再出现空白列表；
  3. `WINEXPLORER_LOAD_DEBUG=1` 启动，切目录时终端应打出 `[Load] gen=… 应用结果 … items=N`，
     若出现 `丢弃过期结果` 但之后没有 `应用结果`，说明卡在上游读取，看门狗会兜住。
